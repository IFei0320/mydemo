# 第6章 总结与展望

## 6.1 工作总结

本文围绕“智能旅游路线规划系统”的设计与实现这一主题，结合 Web 开发、多目标优化算法与知识增强技术，完成了一个集旅游数据展示、智能路线推荐、知识问答和任务导出于一体的本科毕业设计系统。系统以 Django 为开发框架，以旅游景点数据为基础，以 NSGA-II 多目标优化算法为核心，以本地 Markdown 知识库与大语言模型能力为扩展支撑，构建了一个具有一定完整性、实用性和可演示性的旅游辅助决策平台。

从整体研究与实现过程来看，本文主要完成了以下三个方面的工作。

### 6.1.1 完成了基于 NSGA-II 的多目标路线优化算法设计与实现

旅游路线规划并不是一个单一目标问题，用户在实际决策时通常会同时关注预算成本、路程长短、景点评分以及热门程度等多个因素。针对这一特点，本文将旅游路线规划建模为一个多目标优化问题，并采用 NSGA-II 算法作为核心求解方法。通过景点数据清洗、价格解析、坐标校验、季节偏好增强等预处理步骤，系统能够构建同城候选景点集合，并在此基础上利用快速非支配排序、拥挤度距离、锦标赛选择、有序交叉、变异与精英保留等机制，搜索得到一组较优的 Pareto 路线方案。

在此基础上，系统并未停留在“输出全部 Pareto 解”的层面，而是结合用户对价格、距离、热度、评分和拥挤规避的偏好敏感度，从解集中进一步筛选出省钱型、均衡型和体验型三类代表性路线。这使得系统能够更贴近真实用户的选择习惯，也增强了优化结果的可解释性与可用性。实验结果表明，本文方法在成本控制、方案多样性和综合平衡能力方面，相较简单贪心与随机方法具有明显优势，能够满足旅游规划场景中的应用需求。

### 6.1.2 构建了基于 Markdown 的轻量级 RAG 知识库系统

为了解决大语言模型在旅游问答和攻略生成中可能出现的幻觉问题，本文进一步设计并实现了一个基于 Markdown 文档的轻量级 RAG 知识增强模块。系统将原始旅游资料保存在 `raw/` 目录下，通过摘要提取、实体识别、概念归纳与交叉引用构建 `wiki/summary/`、`wiki/entity/` 和 `wiki/concept/` 等知识页面，形成结构清晰、便于维护的本地旅游知识库。

在知识使用阶段，系统能够根据用户问题、目标城市以及路线中涉及的景点信息进行关键词召回和模糊匹配，抽取最佳游玩时段、预约提示、交通建议、避坑信息等知识卡片，并将其注入到 AI Prompt 中，辅助大语言模型生成更具本地化和针对性的旅游建议。这种设计虽然没有引入复杂的向量数据库与语义召回机制，但在本科毕业设计的工程规模下，已经较好地体现了“检索增强生成”的核心思想，也增强了系统结果的可信度与信息解释能力。

### 6.1.3 开发了完整的 Django Web 应用并实现可视化与第三方导出功能

除算法与知识增强部分外，本文还基于 Django 框架完成了一个具有完整功能链路的 Web 应用系统。系统实现了用户注册登录、个人信息管理、头像上传、景点分页浏览、目的地概览生成、智能路线规划、Wiki 问答、数据分析可视化以及滴答清单导出等多个功能模块，形成了较完整的业务闭环。

在前端交互方面，系统基于统一模板组织页面结构，采用较为现代化的卡片式界面和玻璃拟态风格，提高了展示效果；在数据分析方面，系统支持景点评分、热度、门票价格和区域分布等内容的统计展示；在结果落地方面，系统还支持将旅游路线导出为滴答任务清单，使规划结果进一步转化为可执行计划。整体来看，本文不仅完成了算法设计，也完成了面向用户的系统集成与可视化呈现，较好地体现了本科毕业设计中“理论分析 + 系统实现 + 应用验证”的完整研究路径。

## 6.2 存在的不足

尽管本文已经完成了系统设计、关键算法实现与基本实验验证，但受时间、数据规模和开发条件限制，系统仍存在一些不足之处，需要在后续工作中继续完善。

### 6.2.1 知识库检索方式较轻量，语义召回能力有限

当前系统的知识增强模块主要依赖本地 Markdown 页面、规则处理和关键词匹配完成知识召回。该方法实现成本低、易于维护，适合本科毕业设计的小规模知识库场景，但在知识规模扩大后，其检索精度和召回能力会受到限制。尤其当用户提问较为口语化、表达模糊或不直接包含景点关键词时，单纯依赖关键词匹配可能无法准确命中最相关的知识页面，从而影响问答质量和知识增强效果。

### 6.2.2 距离计算采用近似方法，尚未接入真实导航路径规划服务

在当前路线规划模型中，系统主要通过景点之间的球面距离和距市中心距离来估计路线总路程。这种方法实现简单、便于计算，但与真实出行场景仍存在差距。因为用户实际旅行过程中受到道路结构、交通方式、换乘成本、实时拥堵和开放时段等因素影响，真实通行时间与地图直线或球面距离之间并不完全一致。因此，当前模型在路径长度估计上仍然属于一种近似处理。

### 6.2.3 用户偏好建模仍较为简单

目前系统通过滑动条或参数输入的方式，让用户表达对价格、距离、评分、热度和避拥挤等维度的敏感度，再基于这些权重从 Pareto 解集中选出较匹配的路线方案。这种方式实现直观，适合 Web 交互，但本质上仍属于较为静态和粗粒度的偏好建模方法。系统尚未引入用户历史选择行为、个体画像分析或动态偏好学习机制，因此在更复杂的个性化推荐场景下，推荐结果的精细程度仍有提升空间。

## 6.3 未来展望

针对上述不足，本文认为本系统在后续研究和工程实践中还存在较大的改进空间。未来可以从以下几个方向继续完善。

### 6.3.1 引入向量数据库与 Embedding 模型，提升语义检索能力

未来可在现有 Markdown Wiki 知识库基础上，进一步引入向量数据库和文本向量化模型，例如 FAISS、Milvus 或其他 Embedding 检索方案。通过将知识页面切分后向量化存储，系统能够支持更灵活的语义相似度检索，不再完全依赖显式关键词命中。这样不仅可以提升问答质量，还可以使系统在面对更大规模旅游知识库时保持较好的扩展性。

### 6.3.2 接入真实地图与路径规划 API，提升路线评估精度

未来可结合高德地图、百度地图等地图服务接口，获取景点之间更真实的驾车、公交、步行距离与时间信息。这样一来，系统在进行路线优化时就不再只依赖球面距离近似，而是能够根据真实交通网络、换乘方案和道路耗时进行更准确的路线评估。若进一步引入开放时间窗口和交通拥堵信息，还可以将当前模型扩展为更贴近实际旅游场景的时空约束路径优化问题。

### 6.3.3 引入用户历史行为数据，增强个性化推荐能力

在个性化方面，未来可以记录用户曾选择的路线方案、浏览过的景点、导出过的行程及问答偏好，并结合这些行为数据构建更细粒度的用户兴趣画像。在此基础上，可考虑引入协同过滤、内容推荐或交互式偏好学习方法，使系统能够在用户多次使用后逐步学习其真实偏好，从而生成更贴合个人兴趣的旅游规划结果。

### 6.3.4 支持多城市联程规划与跨城衔接

当前系统主要面向单城市旅游路线规划场景，而现实中很多用户会安排跨城市、多目的地的联程旅行。未来可以将系统进一步扩展为支持多城市联程规划，综合考虑城际交通、换乘时间、住宿衔接和不同城市之间的游玩节奏，从而实现更复杂、更完整的中长途旅行方案推荐。该方向不仅具有较强应用价值，也能够进一步提升系统在研究层面的复杂度和创新性。

## 6.4 全文总结

综上所述，本文以智能旅游路线规划为研究对象，围绕“数据驱动的旅游推荐”这一主题，完成了系统需求分析、关键技术研究、NSGA-II 多目标优化算法实现、轻量级 RAG 知识库构建、Django Web 系统开发以及测试实验分析等工作。研究结果表明，本文所设计的系统能够在旅游路线规划场景下较好地平衡成本、距离、评分和热度等多种因素，并通过知识增强和 AI 文本生成提升结果的可读性与实用性。

对于本科毕业设计而言，本文完成的不仅是一个可运行的应用系统，也是在有限工程条件下对“智能优化 + 知识增强 + Web 系统集成”这一复合型技术路线的一次完整实践。虽然系统仍然存在检索精度、距离建模和个性化能力等方面的不足，但其整体设计思路具有一定可扩展性，后续仍有较大的研究和应用深化空间。
