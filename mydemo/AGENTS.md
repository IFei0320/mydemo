# LLM Wiki 构架文件

> 本文件定义 Wiki 知识库的维护规则、文件结构与命名约定。
> 任何 AI Agent 在操作 Wiki 前必须先阅读此文件。

## 一、目录结构

```
mydemo/
├── raw/                    # 原始来源（原料层）—— AI 只读不修改
│   └── *.md / *.txt
├── wiki/
│   ├── summary/            # 摘要页（每份 raw 对应一篇）
│   ├── entity/             # 实体页（景点、餐厅、酒店、地名等）
│   └── concept/            # 概念页（抽象策略标签）
├── index.md                # 自动维护的索引
├── log.md                  # 操作日志
└── AGENTS.md               # 本文件（规则层）
```

## 二、文件类型说明

### 1. 原始来源（raw/）
- 存放用户上传的攻略、文章、截图文字版等。
- **不可被 AI 修改**，AI 只能读取并编译到 wiki/ 中。
- 支持格式：`.md`、`.txt`

### 2. 摘要页（wiki/summary/）
- 由 AI 在摄入（Ingest）阶段自动生成。
- 每份 raw 文件对应一篇 summary。
- 必须包含：标题、来源信息、AI 摘要、交叉引用。

### 3. 实体页（wiki/entity/）
- 记录具体实体：景点名称、餐厅、酒店、交通站点等。
- 跨来源聚合：同一实体在不同 raw 中的描述应合并到同一 entity 页。
- 命名：实体名称本身（如 `外滩.md`、`迪士尼.md`）。

### 4. 概念页（wiki/concept/）
- 记录抽象概念：错峰出行、预算控制、夜景路线、预约策略等。
- 每个概念页包含：定义、适用规则、来源关联、交叉引用。

## 三、交叉引用语法

使用双括号 `[[...]]` 进行页面间链接：

- `[[raw/上海.md]]` —— 指向原始来源
- `[[wiki/summary/上海.md]]` —— 指向摘要页
- `[[实体:外滩]]` —— 指向实体页
- `[[概念:错峰出行]]` —— 指向概念页

## 四、摄入（Ingest）规则

1. 读取 raw/ 下的原始文档。
2. 使用 LLM 深入理解原文，提炼隐含信息。
3. 生成结构化 Markdown 摘要，写入 wiki/summary/。
4. 识别实体，创建或更新 wiki/entity/ 页面。
5. 提炼概念，创建或更新 wiki/concept/ 页面。
6. 在概念页和实体页中建立交叉引用。
7. 更新 index.md 和 log.md。

## 五、查询（Query）规则

1. 先用本地关键词召回 Top-K 相关页面。
2. 读取召回页面的完整内容作为上下文。
3. 使用 LLM 基于上下文生成结构化、带引用的答案。
4. 答案中必须标注信息来源。
5. 若来源冲突，需指出冲突并给出建议。

## 六、检查（Lint）规则

定期执行健康检查：
1. 检查页面之间的矛盾（如 A 说"免费"，B 说"门票 100"）。
2. 检查过时信息（已关闭景点、变化的票价）。
3. 检查遗漏的交叉引用（被提及但未创建的实体/概念）。
4. 检查孤立页面（没有入链的页面）。
5. 检查死链（引用不存在的页面）。
