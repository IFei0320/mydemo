# 滴答导出、前端架构与部署配置

## 一、滴答清单导出（views_dida.py）

### 1.1 概述

`home/views_dida.py` 将 NSGA-II 生成的旅行路线导出为滴答清单（Dida365）的任务。每个景点创建为一个独立任务，按出发日期 + 时段（上午/中午/下午）自动设定开始和截止时间。

### 1.2 配置

```python
DIDA_FIXED_ACCESS_TOKEN = os.getenv('DIDA_ACCESS_TOKEN', '...')
DIDA_FIXED_PROJECT_NAME = os.getenv('DIDA_PROJECT_NAME', '旅游规划')
```

从 `.env` 读取滴答 API 的 access token 和目标项目名称。项目名称支持两种形式：完整 projectId（≥20 字符）或名称（通过 API 查找 ID）。

### 1.3 核心函数

#### _parse_day_slot(visit_time) — 解析时段

从 visit_time 字符串中提取天数编号和时段。例如 `"第1天-上午"` → `(1, "上午")`。

#### _resolve_dida_project_id(access_token, project_input) — 解析项目ID

如果传入的项目名是短名称（非 UUID），调用滴答 `GET /open/v1/project` 接口查找对应的 projectId。如果已经是 ≥20 字符的 ID 则直接返回。

#### export_to_dida_checklist(request) — 主导出视图（POST）

```
1. 解析 JSON 参数（departure_time、city、route、knowledge_cards）
2. 校验 departure_time 和 route 不为空
3. 使用 datetime.fromisoformat 解析出发时间
4. 查找滴答项目
5. 构建知识卡索引
6. 遍历 route 中每个景点：
   a. 根据 visit_time 计算 start/due 时间
   b. 匹配知识卡获取避坑建议
   c. 构建任务描述（含时段、特点、花费、坐标、提醒）
   d. POST 到滴答 /open/v1/task 创建任务
7. 汇总成功/失败结果返回 JSON
```

**任务描述模板**：包含行程时段、景点特点、预计花费、坐标、贴心提醒（最佳时段、预约提示、交通建议、避坑建议）、出发前检查清单。

**时段映射**：上午→9:00，中午→13:00，下午→16:00。每个任务默认 2 小时时长。

**错误处理**：
- 如果全部任务创建失败 → 返回 500
- 部分失败 → 返回 200 但列出 failed_tasks
- HTTP 错误 → 捕获 HTTPError 和 URLError，记录错误信息

### 1.4 知识卡匹配

`_match_knowledge(spot_name)` — 模糊匹配知识卡片。将景点名与知识卡中的 spot_name 做双向子串匹配（"A 包含 B 或 B 包含 A"），匹配成功则返回对应知识卡（最佳时段、预约提示、交通建议、避坑建议）。

## 二、前端模板架构

### 2.1 全局基础模板（base.html）

`templates/base.html` 定义了全局布局框架，所有业务页面（除登录/注册外）继承它。

**布局结构**：
```
┌─────────────────────────────────────────┐
│  顶栏（.pcoded-header）56px             │
│  品牌Logo | 搜索框 | 全屏按钮           │
├──────────┬──────────────────────────────┤
│ 侧边栏    │  主内容区                     │
│ 260px    │  .pcoded-main-container      │
│          │                              │
│ 用户信息  │  {% block content %}         │
│ 下拉菜单  │  （各页面填充）               │
│ 导航菜单  │                              │
└──────────┴──────────────────────────────┘
```

**侧边栏导航菜单**：

| 分组 | 菜单项 | 对应 URL |
|------|--------|----------|
| 布局 | 首页 | /mydemo/index |
| 布局 | 国内旅游景点 | /mydemo/travel_list |
| 数据分析 | 景点评分信息 | /ksh/part1 |
| 数据分析 | 景点热度分析 | /ksh/part2 |
| 数据分析 | 门票价格分析 | /ksh/part3 |
| 数据分析 | 景点地区分布 | /ksh/part4 |
| 智能出行 | 目的地速览 | /mydemo/get_ai_travelRoute |
| 智能出行 | 智能路线规划 | /mydemo/ai_nsga2_route |
| 智能出行 | LLM Wiki MVP | /mydemo/wiki_mvp |

**关键 JS 功能**：
- **CSRF Token 注入**：从 cookie 读取 csrftoken，通过 `$.ajaxSetup` 为所有非 GET AJAX 请求自动添加 `X-CSRFToken` 请求头
- **侧边栏高亮**：根据当前 URL 路径自动匹配并高亮对应菜单项
- **data-url 导航**：侧边栏链接使用 `data-url` 属性（而非 href），通过事件委托实现跳转
- **全屏切换**：`toggleFullScreen()` 使用 Fullscreen API
- **移动端响应**：≤992px 宽度时侧边栏通过平移（translateX）切换显示
- **用户下拉**：点击用户名展开/折叠退出和个人信息菜单
- **预加载器**：页面加载完成后 500ms 淡出 loading 动画

### 2.2 独立页面

## 三、前端 JS 详解

### 3.1 ai_nsga2_route.js — 智能路线规划页

**功能模块**：

**1. 滑块绑定**：5 个敏感性滑块与数值标签实时联动（price/distance/hotness/rating/crowd）。

**2. 百度地图渲染（renderMap）**：
- 按天分组路线点，用不同颜色区分（红/蓝/绿/黄/紫/青）
- 标记编号（数字标签）+ InfoWindow 点击弹窗
- 同日相邻景点间绘制方向箭头
- 自动调整视口（setViewport）适配所有点位
- 无效坐标（非中国范围）自动跳过

**3. 路线表格（renderTable）**：序号 + 景点名（带图标）+ 时段标签 + 特色 + 费用 + 坐标。

**4. 知识卡渲染（renderKnowledgeCards）**：编号圆标 + 景点名 + 四格信息（最佳时段/预约提示/交通提示/避坑点）。

**5. Top3 方案卡片（renderTop3）**：三张渐变色卡片展示 economics/balanced/experience，每张含 7 个指标和选择按钮。

**6. AI 报告处理**：
- `sanitizeHtmlForPreview()` — 移除 script 标签，补全 HTML 结构
- `openHtmlReport()` — 新窗口预览
- `downloadHtmlReport()` — Blob 下载

**7. 滴答导出流程**：
- 点击导出按钮 → 弹出模态框选出发时间 → 确认 → AJAX 发送路线 + 知识卡到后端 → 显示创建结果

**8. 主流程**：
- 表单提交 → AJAX POST 生成路线 → 渲染 Top3 卡片
- 用户选择方案 → AJAX POST 确认 → 渲染地图 + 表格 + 知识卡 + AI 文本 + HTML 报告

**数据流**：
```
[表单] → generate_ai_nsga2_route API → Top3 预览
                                           ↓ 用户选择
                                     select_ai_nsga2_plan API → 完整结果
                                           ↓
                              地图 + 表格 + 知识卡 + AI报告 + 导出
```

### 3.2 get_ai_travelRoute.js — AI 目的地速览页

**功能模块**：

**1. 百度地图管理**：
- `initMap()` — 初始化地图实例，添加导航/比例尺/缩略图控件
- `markDatasetSpots()` — 标注景点（Marker + InfoWindow），自动调整视口
- `clearMap()` — 清除所有覆盖物
- `bindMapAfterResultVisible()` — 结果容器显示后重新绑定地图（解决隐藏容器中地图尺寸问题，通过 checkResize 多次调整）

**2. UI 辅助**：
- `showLoading()` / `hideLoading()` / `showResult()` — 带滚动动画的状态切换
- `showError()` / `hideError()` — 错误提示管理
- `escapeHtml()` — XSS 防护

**3. 结果渲染（renderOverview）**：
- 城市概述 → `#citySummary`
- 值得看的 → `#whatToSeeList`（li 列表）
- 注意事项 → `#watchoutsList`（li 列表，警告样式）
- 片区主题 → `#regionsBox`（region-card 卡片）
- 解析备注 → `#parseNoteBox`（LLM 容错提示）
- 统计计数 → 亮点数/注意事项数/地图标注数

**4. 主流程**：
```
[表单] → POST /mydemo/get_ai_travelRoute → JSON
  → renderOverview() 填充文本卡片
  → showResult() 展开结果区
  → bindMapAfterResultVisible() 渲染地图标注
```

### 3.3 wiki_mvp.js — Wiki 知识库管理页

使用原生 `fetch` API（非 jQuery），简洁的异步操作：

- `callApi(url, payload)` — 通用 POST 封装，自动注入 CSRF token
- `formatQueryResult(res)` — 将查询结果格式化为"答案 + 来源页面列表"的纯文本
- 三个按钮：摄入（ingest）、健康检查（lint）、查询（query）

### 3.4 part1.js — 景点评分信息页

两个 ECharts 图表：
- **饼图**（玫瑰环形）：评分分布占比，半透明玻璃质感
- **组合图**（柱状 + 折线）：各省份景点数量（柱状渐变）与平均评分（粉色折线），双 Y 轴，含 dataZoom 缩放条和 toolbox（数据视图/切换类型/还原/保存图片）

数据来源：`window.part1Config`（由 Django 视图通过模板变量注入）。

### 3.5 part2.js — 景点热度分析页

两个 ECharts 图表 + 城市异步筛选：

- **漏斗图**：各景点评论数排行（倒三角漏斗）
- **柱状图**：城市热度评分横向柱状图，渐变配色

**城市筛选交互**：
```
下拉框 change → AJAX GET /ksh/get_cityData?city=XX → 更新柱状图数据
```

这是唯一一个通过 AJAX 异步加载数据的图表页（其他页的数据都在页面加载时通过模板变量注入）。

### 5.4 CSRF 防护策略

项目使用 Django 标准的 CSRF 双重防护：

1. **后端**：`CsrfViewMiddleware` 对所有 POST/PUT/DELETE 请求校验 `X-CSRFToken` 请求头
2. **前端**：
   - base.html 中 `{% csrf_token %}` 触发 Django 设置 csrftoken cookie
   - `getCsrfToken()` 从 cookie 读取 token，挂载到 `window.csrfToken`
   - `$.ajaxSetup` 为所有非安全方法的 jQuery AJAX 自动添加 `X-CSRFToken` 头
   - wiki_mvp.js（fetch API）手动从 `window.csrfToken` 读取并设置
   - login.html / register.html（独立页面）各自包含完整的 CSRF 注入代码

## 六、百度地图 API 集成

两个页面使用百度地图 JS API：

| 页面 | 用途 | 渲染时机 |
|------|------|----------|
| get_ai_travelRoute | 标注数据库匹配景点 | 结果容器显示后（解决隐藏容器尺寸问题） |
| ai_nsga2_route | 标注路线点 + 连线 + 箭头 | 选择方案后 |

**常见问题处理**：
- 隐藏在 `display:none` 容器中的地图需要 `checkResize()` 重绘
- `map.getViewport()` 自动计算最佳视口
- 坐标校验：`isValidChinaCoord()` 过滤境外坐标（中国范围：lon 73~136, lat 3~54）
