# 用户系统与业务模块

## 一、用户系统（user/）

### 1. 模块概述

用户模块处理登录、注册、个人信息修改、头像上传、登出。使用 Django Session 管理登录态。

### 2. 视图函数详解（user/views.py）

#### login(request) — 第14行

```
GET  → 渲染 login.html
POST → 验证用户名密码 → 写入 session → 返回 JSON
```

**处理流程**：
1. 从 POST 数据获取 username 和 password
2. 用 `UserInfo.objects.get(username=username)` 查找用户
3. 用 `check_password(password, user.password)` 验证（Django 的哈希比对）
4. 成功后将 `uid`、`uname`、`avatar` 写入 `request.session`
5. 返回 JSON：`{code: 200, msg: '登录成功'}`

#### register(request) — 第48行

```
GET  → 渲染 register.html
POST → 校验 → 创建用户 → 返回 JSON
```

**处理流程**：
1. 检查用户名是否已存在（`UserInfo.objects.filter(username=username).exists()`）
2. 检查邮箱是否已存在
3. 用 `make_password(password)` 哈希密码后创建用户
4. 返回 JSON

#### changeInfo(request) — 第80行

```
GET  → 读取用户信息 → 渲染 changeInfo.html
POST → 更新用户信息 → 返回结果
```

**处理流程**：
1. 从 session 读取 uid 确认登录
2. GET：查询用户显示在表单中
3. POST：校验用户名/邮箱不与其他用户冲突 → 更新 → 同步 session 中的 `uname` 和 `avatar`

#### upload_avatar(request) — 第152行

```
POST → 接收文件 → 校验 → 存储 → 更新DB → 返回JSON
```

**安全校验**：
- 文件类型白名单：JPEG / PNG / GIF / WebP
- 文件大小限制：2MB

**处理流程**：
1. 检查登录态（session uid）
2. 验证文件类型和大小
3. 创建 `media/avatars/` 目录（如不存在）
4. 生成文件名：`avatar_{uid}_{timestamp}.{ext}`
5. 写入文件
6. 更新 `user.avatar` 字段为 `/media/avatars/{filename}`
7. 同步 session 中的头像路径

#### logout(request) — 第214行

清空 session，重定向到登录页。

## 二、首页仪表盘（home/views.py — index）

### 1. URL：`/mydemo/` 或 `/mydemo/index`

### 2. 数据查询

首页展示 6 组统计数据：

| 统计项 | 查询方式 | 说明 |
|--------|----------|------|
| 收费景区数量 | ORM：exclude actual_price='免费' | 统计有票价的景点数 |
| 覆盖省份 | ORM：distinct province count | 数据覆盖的省份数量 |

| 热度TOP5 | ORM：order_by popularity_score[:5] | 侧边排行卡片 |
| 评论TOP10 | ORM：order_by review_count[:5] | 表格展示 |
| 用户增长 | ORM：UserInfo 按创建日期分组 count | 柱状图 |

### 3. 数据流

```
Django View (index)
  ├── TravelInfo ORM 查询 → 统计数字 → context
  ├── util.query("select * from part6") → mapData → context
  ├── UserInfo ORM 分组 → name_list, value_list → context
  └── render('index.html', context)  →  ECharts渲染
```

## 四、KSH 数据可视化分析模块（ksh/views.py）

### 1. 模块概述

KSH 模块提供 4 个数据分析页面，使用 ECharts 渲染交互式图表。Part1、Part2 通过 pymysql 查询离线分析表；Part3、Part4 改用 Django ORM 查询 TravelInfo。

### 2. 视图函数详解

#### part1(request) — 景点评分信息

**数据来源**：
- `part1` 表：景点评分分布数据
- `part8` 表：各景点名称、数量、平均评分

**传给前端的数据**：
- `data_list`：评分分布（饼图/柱状图数据）
- `name_list` + `travel_num_list` + `avg_score_list`：各景点数量与平均分对比

#### part2(request) — 景点热度分析

**数据来源**：
- `part2` 表：热度分析数据
- `part7` 表：各城市的景点分布（用于下拉筛选器）

**传给前端的数据**：
- `data_list`、`name_list`：热度图表数据
- `select_list`：城市下拉选项列表

#### get_cityData(request) — 城市数据异步查询

```
GET /ksh/get_cityData?city=上海
→ 参数化查询 part7 表
→ 返回 JSON：{data: {names: [...], values: [...]}}
```

此接口被前端 Part2 页面的城市下拉框切换时通过 AJAX 调用。

#### part3(request) — 门票价格分析

**双模式设计**：

| 模式 | 触发条件 | 展示内容 |
|------|----------|----------|
| 汇总模式 | 未选择省份 | 各省份平均门票价格降序排列 |
| 详情模式 | 选择了某省份 | 该省各景点价格（免费景点=0元） |

**价格解析逻辑**：
1. 若 `is_free=True` → 价格=0
2. 否则优先用 `actual_price`，为0则用 `market_price`
3. `_parse_price()` 将字符串转为浮点数

#### part4(request) — 景点地区分布

**核心算法：自动降级策略**

因为数据中"所在区域"字段可能过细（一个区只有1个景点），图表会变成"全是100%占比"的无意义状态。part4 实现了三层自动降级：

```
第一层：按 area 聚合
  ↓ 如果多数区域只有1个景点（退化）
第二层：降级为按 city 聚合
  ↓ 如果城市也只有1个（单城市数据）
第三层：从 area 文本中正则抽取"XX区/县"关键词再聚合
  ↓ 如果全部失败
兜底：读取离线表 part4
```

函数 `_is_degenerate()` 判断是否退化：如果70%的分组 count=1 或超过12个分组中55%是 count=1。

## 五、用户登录与注册的前端

### login.html 和 register.html

这两个是**独立页面**（不继承 base.html），因为它们有完全不同的布局（全屏居中玻璃卡片）。

**登录页 JS 流程**：
1. 表单提交 → `e.preventDefault()` 阻止默认提交
2. jQuery `$.ajax POST` 到 `/user/login`
3. 成功（code=200）→ 跳转 `/mydemo/`
4. 失败 → alert 错误信息

**注册页 JS 流程**：
1. 前端校验两次密码一致
2. jQuery `$.ajax POST` 到 `/user/register`
3. 成功 → 显示 toast 提示 → 跳转登录页
4. 失败 → toast 显示错误

CSRF token 通过 cookie 读取 + `$.ajaxSetup` 自动注入（已配置）。
