#### 2.2 多目标优化与NSGA-II算法（1500~2000字）【重点】

**这是论文的理论核心，必须写透。**

**2.2.1 多目标优化问题定义**

写出标准数学模型：

```
min F(x) = [f₁(x), f₂(x), ..., fₘ(x)]
s.t.  gᵢ(x) ≤ 0,  i = 1, 2, ..., p
      hⱼ(x) = 0,  j = 1, 2, ..., q
      x ∈ Ω
```

解释：
- 目标函数向量 F(x)
- 决策变量 x（本系统中为景点序列）
- 约束条件（预算、天数、开放时间等）
- Pareto支配关系定义（写数学公式）

**2.2.2 NSGA-II算法原理**

按以下顺序写：
1. 快速非支配排序（Fast Non-dominated Sorting）
2. 拥挤度距离（Crowding Distance）
3. 锦标赛选择（Tournament Selection）
4. 有序交叉（Order Crossover, OX）
5. 变异操作（Swap / Insert Mutation）
6. 精英保留策略

**每个算法步骤都要配伪代码。**

快速非支配排序伪代码模板：
```
算法1: Fast Non-dominated Sorting
输入: 种群 P
输出: 非支配前沿 F = {F₁, F₂, ...}

1.  for each p ∈ P do
2.      Sₚ = ∅      // p 支配的解集
3.      nₚ = 0      // 支配 p 的解数量
4.      for each q ∈ P do
5.          if p ≺ q then Sₚ = Sₚ ∪ {q}
6.          else if q ≺ p then nₚ = nₚ + 1
7.      if nₚ = 0 then rank(p) = 1; F₁ = F₁ ∪ {p}
8.  i = 1
9.  while Fᵢ ≠ ∅ do
10.     Q = ∅
11.     for each p ∈ Fᵢ do
12.         for each q ∈ Sₚ do
13.             n_q = n_q - 1
14.             if n_q = 0 then rank(q) = i+1; Q = Q ∪ {q}
15.     i = i + 1; Fᵢ = Q
```

**2.2.3 旅游路线规划的多目标建模**

写出本系统的具体目标函数：

```
f₁(x) = Σ cost(xᵢ)          // 总门票成本（最小化）
f₂(x) = Σ distance(xᵢ, xᵢ₊₁)  // 总路程（最小化）
f₃(x) = -Σ rating(xᵢ) / n   // 平均评分（最大化，取负后最小化）
f₄(x) = -Σ hotness(xᵢ) / n  // 平均热度（最大化，取负后最小化）
```

约束条件：
```
g₁(x): Σ cost(xᵢ) ≤ budget      // 预算约束
g₂(x): |x| ≤ days × 3          // 每日最多3个景点
g₃(x): xᵢ ∈ City_A, ∀i        // 同城约束
```

**4.3.2 NSGA-II算法实现**

按以下子模块逐一说明：

**(1) 染色体编码**
```
染色体 = [景点索引₁, 景点索引₂, ..., 景点索引ₙ]
其中 n = days × per_day（每天3个景点）
```

**(2) 适应度评估**

解释：
- 可行解：cost ≤ budget，目标为 [cost, distance, -rating, -hotness]
- 不可行解：施加惩罚函数，目标值设为极大值

**(3) 遗传操作**

交叉：有序交叉（OX）——配示意图
变异：交换变异 + 替换变异

**(4) Pareto前沿选择与方案排序**

- 如何从Pareto前沿选出Top3
- 经济型：min(cost)
- 体验型：max(rating × 0.6 + hotness × 0.4)
- 均衡型：基于用户敏感度加权

### 9.2 答辩高频问题与回答准备

**Q1：为什么选择NSGA-II而不是其他算法？**
> A：旅游路线规划涉及成本、距离、评分、热度多个相互冲突的目标，属于典型的多目标优化问题。NSGA-II通过快速非支配排序和拥挤度距离，能在一次运行中得到一组Pareto最优解，便于用户根据偏好权衡选择，相比单目标算法（如贪心）或需要多次运行的加权和方法效率更高。

**Q2：你的RAG和标准的向量数据库RAG有什么区别？**
> A：本系统采用轻量级方案，基于Markdown文件结构和关键词匹配实现检索，未引入向量数据库。这样做的好处是部署简单、无需额外服务。不足是语义检索能力有限，未来可升级为Embedding+向量数据库方案。

**Q3：数据来源是什么？数据量多大？**
> A：景点数据通过Python爬虫从在线旅游平台获取，经过去重、缺失值填充、格式标准化后入库。当前有效数据约120条（上海），覆盖景点名称、位置、评分、价格、标签等字段。系统架构支持其他城市数据扩展。

**Q4：预算约束是怎么处理的？**
> A：在NSGA-II的适应度评估中，若路线总成本超过预算，则施加惩罚函数，将目标值设为极大值，使不可行解在排序中被淘汰。这样可以保证最终输出的方案都满足预算约束。

**Q5：系统的实际应用价值在哪里？**
> A：相比传统攻略需要游客手动筛选和排序，本系统能在秒级生成满足个人预算和偏好的多条候选路线，并提供可直接执行的HTML攻略和任务清单，显著降低规划成本。
